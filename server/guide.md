# Kanb 使用指南（AI 版）

> 本文件内嵌于 kanb server，经 `GET /api/guide` 提供（公开只读），供 MCP 客户端经
> `get_usage_guide` 工具或 `kanb://guide` 资源按需读取。约定与 `docs/mcp.md` 同步维护：
> **修改任一处，需同步另一处**（docs 面向人，本文件面向模型）。

## 这是什么

Kanb 是团队任务看板。任务按状态分列流转，支持标签、截止日、多人认领、进度记录、
前置依赖与评论。AI 通常这样被使用：查重 → 建任务 → 加依赖 → 认领 → 报进度。

## 任务与写操作约定

- **task_id 来源**：来自 `list_tasks`/`get_task`/`create_task` 返回 JSON 的 `id` 字段，
  不要臆造；写操作前建议先用只读工具确认目标存在。
- **状态 status**：`todo`（待认领）/ `in_progress`（进行中）/ `done`（已完成）/
  `abandoned`（已废弃，终态）。新建默认 `todo`；未完成/未废弃任务才计逾期与阻塞。
- **due_date**：`YYYY-MM-DD`（如 2026-09-12）；空/省略 = 无截止。
- **tags**：字符串数组。
- **认领**：可多人认领同一任务；取消认领仅影响当前账号自己的认领。
- **进度**：`percent` 为 0-100 整数；追加式记录（多次报进度 = 多条记录，非覆盖）。
- **依赖**：`task_id` 依赖 `dep_id`（先完成它）；服务端防成环。依赖目标处于终态
  （已完成/已废弃）即不再阻塞——不要给已终态任务追加依赖。
- **删除**：删除走回收站（可恢复），不是物理清除；清理需在回收站另行操作。
- **评论**：支持 Markdown、1-2000 字符；顶层评论可被回复；编辑/删除仅限本人或管理员。

## 操作建议（先查后写）

1. 创建任务前先 `list_tasks` 查重（按标题/标签判断），避免重复。
2. 拆解大任务：先逐个 `create_task` 收集返回 id，再 `add_dependency` 连线，
   最后 `claim_task` / `add_progress`。
3. 想知道「谁在做什么」用 `list_activities`；想了解某任务全貌用 `get_task`。

## 错误信息速读（服务端返回中文）

- `400`：参数不合法（无效状态、标题为空、percent 越界等）——按提示修正后重试。
- `403`：无权限（改/删他人评论、删他人任务等）——不要反复重试，向用户说明。
- `404`：目标不存在或已被删除——先列表确认再决定。
- `401`：会话失效，MCP 进程会自动重登并重放一次；持续失败请检查账号凭据配置。

## 端到端示例

拆「做登录页」（前置「画原型」）：
1. `list_tasks` 查重；
2. `create_task {title: 画原型, tags: [设计]}` → 得 id A；
3. `create_task {title: 做登录页, tags: [前端]}` → 得 id B；
4. `add_dependency {task_id: B, dep_id: A}`；
5. `claim_task {task_id: B}`；`add_progress {task_id: B, percent: 10, text: 开始}`。
